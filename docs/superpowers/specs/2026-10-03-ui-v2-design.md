# gpui-tunes UI v2 design

Three additions to the v1 player, built in order on branch `feat/ui-v2`:

1. Chrome polish: collapsible sidebar, status bar, keyboard shortcuts, selection reset.
2. Shuffle, repeat, and a read-only Up Next panel.
3. An album-art grid for the Albums section, with cover art loaded off the UI thread.

Each part is independently shippable and gets its own code review before the next
starts. The v1 rules still hold: `tunes-core` never imports gpui, and `gpui-tunes`
never reads tags, touches the audio device, or filters tracks itself.

Out of scope: playlists, queue editing (reorder, remove, Play Next), lyrics,
a larger now-playing panel, library persistence, metadata editing.

## Part 1: Chrome polish

### Collapsible sidebar

- `AppView` holds `sidebar_collapsed: bool`. A toolbar button at the far left and
  `ctrl+B` toggle it.
- Collapsed, the sidebar renders as an icon-only rail (gpui-component `Sidebar`
  collapsed mode) at a fixed narrow width; the section icons stay clickable.
  Expanded, it returns to its previous resizable width.
- `Toolbar` emits a new `ToolbarEvent::ToggleSidebar`; `LibrarySidebar` gets
  `set_collapsed(bool)`.

### Status bar

- New view-less element rendered by `AppView` under the content area: one thin row,
  muted text, centred, e.g. `473 songs, 31:04:12`.
- It describes the rows currently in the song table (after browser, grid, and search
  filters), so it changes as the filter changes.
- `format.rs` gains `fmt_total(Duration) -> String`: `m:ss` under an hour,
  `h:mm:ss` under a day, `d:hh:mm:ss` beyond. Unit tested.
- Count and total are computed once in `apply_query`, not on every render.
- Hidden while scanning or when the library folder is missing.

### Keyboard shortcuts

Implemented as gpui actions bound in `main.rs` and handled on `AppView`'s root
element.

| Key | Action |
| --- | --- |
| `space` | Play / pause |
| `ctrl+right` | Next track |
| `ctrl+left` | Previous track |
| `ctrl+F` | Focus the search field |
| `ctrl+B` | Toggle the sidebar |
| `enter` | Play the selected table row |

`space` and `enter` are bound in the app's own key context so that they keep their
normal meaning inside the search input (typing a space; no-op). `ctrl+F` and `ctrl+B`
work everywhere, including while the search field has focus. `ctrl+left` and `ctrl+right` change track everywhere except inside the search field, where they move the caret by word as in any text input.

### Selection reset

`apply_query` clears the table's selected row whenever the filter (not just the
sort) changed, so a stale highlight never points at a different track.

## Part 2: Shuffle, repeat, Up Next

### Core: `tunes_core::queue`

`Queue` keeps its existing API and gains:

- `pub enum Repeat { Off, All, One }` (default `Off`).
- `set_shuffle(bool)`, `shuffle() -> bool`, `set_repeat(Repeat)`, `repeat() -> Repeat`.
- `upcoming(n: usize) -> Vec<TrackId>`: the next `n` tracks that `next()` would
  yield, in order, without moving the cursor.
- `advance() -> Option<TrackId>`: what to play when a track ends naturally.
  `Repeat::One` returns the current track again; otherwise it behaves like `next()`.
- `start_at(TrackId) -> bool`: begin from a track the user picked in the table or
  grid. Like `jump_to`, but with shuffle on it reshuffles so that track is first
  and everything else follows it. `jump_to` (used by Up Next) only moves the cursor.

Shuffle design: the queue stores a second vector, `play_order`, which is a
permutation of `order`. With shuffle off it equals `order`. Turning shuffle on
shuffles it with the current track moved to the front; turning it off restores
`order` and keeps the cursor on the current track. `next`, `prev`, `upcoming`, and
`current` all walk `play_order`, so Previous retraces real history and Up Next
shows what will actually play. `order()` still returns the visible (table) order.

Alternatives rejected: choosing a random track on each `next()` (no stable Up
Next, Previous cannot go back) and shuffling the table rows themselves (destroys
the user's sort).

`set_order` while shuffled reshuffles the new order, keeping the current track
first if it is still present.

Randomness: `Queue::new()` seeds a small internal PRNG from the clock;
`Queue::with_seed(u64)` gives tests a deterministic shuffle. No new dependency
beyond `fastrand`.

End of queue, a behaviour change from v1 (which always wrapped):

| Repeat | `next()` at the last track | Natural end of the last track |
| --- | --- | --- |
| `Off` | returns `None`; playback stops | stops |
| `All` | wraps to the first; reshuffles first if shuffle is on | same as `next()` |
| `One` | advances like `All` | replays the same track |

`prev()` at the first track returns `None` under `Off` and wraps under `All`/`One`.
`upcoming` follows the same rules: under `Off` it ends at the end of the queue;
under `All` it continues around; under `One` it lists what manual Next would give.
With shuffle on it always ends at the end of the current pass, because the next
pass is reshuffled only when it starts.

### UI

- `Toolbar` gets three toggle buttons right of the transport controls: shuffle,
  repeat (cycles Off → All → One, with a distinct icon or badge for One), and
  Up Next. New events: `ToolbarEvent::{ToggleShuffle, CycleRepeat, ToggleUpNext}`.
  `ToolbarModel` gains `shuffle: bool`, `repeat: Repeat`, `up_next_open: bool` so
  the buttons render their active state from the model.
- `AppView::tick` calls `queue.advance()` on `TrackEnded` instead of `next()`.
  When `next`/`advance` returns `None` the player is left stopped and the cursor
  stays on the last track.
- New file `ui/up_next.rs`, `UpNextPanel`: a resizable right-hand panel (default
  260 px, range 200–400), shown only when toggled on. Header "Up Next", then a
  list of up to 50 rows from `queue.upcoming(50)`, each showing title and
  `artist — album`. Empty state: "Nothing up next".
- The panel renders from a plain `Vec<TrackId>` plus `Arc<Library>` pushed in by
  `AppView` whenever the queue, the current track, shuffle, or repeat changes.
- Double-clicking a row emits `UpNextEvent::Play(TrackId)`; `AppView` plays it via
  the existing `play_track`. The panel is otherwise read-only.

## Part 3: Album grid

### Core: `tunes_core::library`

- `pub struct AlbumSummary { name: String, artist: String, year: Option<u32>,
  track_count: usize, art_track: Option<TrackId> }`.
- `Library::album_summaries() -> &[AlbumSummary]`, built once in `Library::new`,
  sorted like `albums()` (case-insensitive by name).
- Albums stay keyed by name, matching `Filter.album`. `artist` is the common
  artist of the album's tracks, or `"Various Artists"` when they differ. `year` is
  the earliest year present. `art_track` is the first track (disc, then track
  number) with `has_art`.

### Cover art off the UI thread

New file `ui/art_cache.rs`, `ArtCache`, an entity owned by `AppView` and shared
with the toolbar path and the grid:

- `get(id, cx) -> ArtState`, where `ArtState` is
  `Loading | Ready(Arc<RenderImage>) | Missing`. Every image is decoded and
  downscaled to at most 320 px on the long edge; the toolbar and the grid share
  that one size.
- `Library::cover_art` stops memoizing raw bytes in core: the UI cache keeps the
  thumbnails, so holding every album's full-size picture as well would only cost
  memory.
- A miss returns `Loading`, spawns `library.cover_art(id)` plus decode and resize
  on the background executor, stores the result, and notifies observers. Duplicate
  requests for an in-flight id do not spawn again.
- `AppView::push_toolbar_model` reads from the cache instead of decoding inline,
  which removes the UI-thread read deferred from v1. `art_cache: Option<(TrackId,
  ...)>` on `AppView` goes away.
- No eviction: about a hundred 320 px thumbnails is a few tens of megabytes.

### Grid view

New file `ui/album_grid.rs`, `AlbumGrid`:

- In the Albums section it replaces `ColumnBrowser` in the top pane of the
  vertical split; every other section is unchanged. The top pane's default height
  in Albums is larger (about 360 px) so two rows of tiles are visible.
- Tiles are 160 px wide: square art, then album name and artist, each truncated to
  one line. Albums without art, and art still loading, show a placeholder disc
  icon on a muted background.
- The number of columns is computed from the pane width; rows are virtualized with
  `uniform_list`, so only visible tiles request art.
- Click selects a tile (accent ring) and emits `AlbumGridEvent::Select(Some(name))`;
  clicking the selected tile again emits `Select(None)`. `AppView` sets
  `filter.album` accordingly and reruns the query, exactly as it does for a
  browser change.
- Double-click emits `AlbumGridEvent::Play(name)`: `AppView` selects the album,
  then plays the first row of the resulting table.
- The search field filters the song table only; the grid always shows every album.
- Leaving the Albums section clears the grid selection, matching how the browser
  clears its selections on a section change.

## Data flow additions

```
Toolbar ToggleShuffle/CycleRepeat ──▶ AppView mutates Queue ──▶ UpNextPanel rows
Player TrackEnded ──▶ AppView queue.advance() ──▶ play_track or stay stopped
AlbumGrid Select ──▶ AppView filter.album ──▶ library.query ──▶ table + queue + status bar
AlbumGrid / Toolbar ──▶ ArtCache.get ──background──▶ notify ──▶ re-render
```

## Error handling

- Cover art that fails to decode is cached as `Missing` and logged once with
  `tracing::warn!`; the placeholder is shown.
- An Up Next row whose track is no longer in the queue (the filter changed between
  render and click) is ignored.
- All existing v1 error behaviour (no audio device, decode failure auto-skip,
  missing library folder) is unchanged.

## Testing

- `tunes-core` unit tests, written first:
  - Queue: shuffle is a permutation with the current track first; unshuffle
    restores order and cursor; `prev` retraces shuffled history; `upcoming` matches
    successive `next()` calls under each repeat mode; end-of-queue table above;
    `advance` under `Repeat::One`; `set_order` while shuffled.
  - Library: `album_summaries` counts, Various Artists, earliest year, `art_track`
    choice, sort order.
- `gpui-tunes`: `fmt_total` unit tests. Everything else is verified by running the
  app against the real library and screenshotting: sidebar collapsed and expanded,
  status bar under different filters, each shortcut, shuffle and repeat states,
  Up Next open, the album grid at wide and narrow widths.
- `cargo fmt`, `cargo clippy --workspace --all-targets`, and
  `cargo test --workspace` clean before each commit.
